NeuroGuide: fix 404 on https://<api-id>.execute-api.../api/v1/...
================================================================

Your FastAPI app is correct: routes live under the prefix /api/v1 (see app.main).
The Lambda handler app.main.handler matches the repo. A 404 from execute-api
usually means API Gateway has no route that sends that path to the Lambda (the
request never hits FastAPI, or the path is wrong).

1) Prove the Lambda code is fine (optional)
   - Lambda → neuroguide-api → Test
   - Create an event from file: backend/scripts/lambda-apigw-v2-post-register.json
   - Run test
   - If you get 503: "PASS_KEY_PEPPER" or "DATABASE_URL" / table errors, routing
     works; fix env vars and RDS. If you get 404 in the response body, say so
     (rare if the test event path is /api/v1/pg/session/register).

2) Fix API Gateway HTTP API (most likely)
   - API Gateway → APIs → open the API whose ID matches your browser URL
     (e.g. z7s8pudd5d) → Routes.
   - You need the browser path to be handled. Either:
     A) Add a catch-all (recommended):
        - ANY  /api/v1/{proxy+}  → integration: Lambda neuroguide-api
        (Or ANY /{proxy+} if you do not use a custom parent path.)
     B) Or add an explicit route:
        - POST /api/v1/pg/session/register → same Lambda
   - Use "Lambda proxy integration" (payload format 2.0 for HTTP API).
   - After saving, use "Deploy" if your API type still uses stages; HTTP APIs
     with $default often apply immediately.

3) Two triggers on the Lambda
   - If you have two API Gateways, confirm the frontend VITE_API_BASE_URL points
     to the one that has the /api/v1 routes. The other API can 404.

4) Lambda environment (after 404 is fixed)
   - DATABASE_URL
   - PASS_KEY_PEPPER
   - CORS: allow your site origin (or use API Gateway CORS for browser calls)

5) Redeploy backend after code changes
   - GitHub Action deploy-backend.yml updates neuroguide-api from main when
     backend/** changes. Push to main or upload a new zip if you changed code.

Quick CLI (aws cli configured for ap-southeast-2):
  aws apigatewayv2 get-routes --api-id <YOUR_API_ID> --region ap-southeast-2

If the listed paths do not include your URL, add the catch-all or explicit route.
